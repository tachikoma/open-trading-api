# 캐시 정책 (FDR 캐시)

이 문서는 FinanceDataReader(FDR) 기반의 로컬 캐시 동작과 운영 지침을 설명합니다.

## 개요
- 캐시 위치: `Config.FDR_CACHE_DIR` (기본값: `trading_bot/data/fdr_cache`) 
- 파일 형식: Parquet(.parquet) 우선 + CSV(.csv) 보조
- 동작 요지: 요청된 기간에서 누락된 구간만 증분 다운로드하여 기존 캐시와 병합합니다.

## 동작 상세
1. 캐시 로드
   - Parquet와 CSV가 모두 존재하면 최신 수정시간을 비교해 최신 파일을 사용합니다.
   - Parquet 읽기 실패 시 CSV로 폴백합니다.

2. 증분 갱신
   - 캐시에 저장된 기간이 요청 기간을 완전히 포함하면 캐시에서 바로 서브셋을 반환합니다.
   - 앞/뒤에 누락 구간이 있으면 해당 구간만 다운로드합니다.
   - 요청 기간 내부에 결손(영업일 기준)이 있으면 내부 누락일을 연속 범위로 묶어 다운로드합니다.
   - 다운로드한 파트와 기존 캐시를 병합한 뒤 중복(date) 제거 및 정렬을 수행합니다.

3. 원자적 저장
   - 병합 후 저장은 안전하게 수행됩니다: 임시 파일로 먼저 쓰고 기존 파일로 대체합니다.
   - 저장 순서: CSV로 먼저 저장(항상 시도) → 기존 Parquet가 있으면 제거 → Parquet로 임시 쓰기 후 교체(선택적).
   - 이 방식은 Parquet 작성에 실패하더라도(예: 엔진 문제) CSV를 통해 캐시가 갱신되도록 보장합니다.

4. 로깅
   - 캐시 동작(누락 구간 다운로드, CSV/Parquet 저장 성공/실패)을 로그로 출력합니다.

## 운영 가이드
- 전체 재다운로드가 필요하면 대상 심볼의 캐시 파일을 삭제하세요(`rm <symbol>.parquet <symbol>.csv`).
- 캐시 무결성 점검: 캐시가 오래된 경우(예: 날짜 범위가 요청과 다름) 삭제 후 재다운로드를 권장합니다.
- 성능 팁: 최초 대량 갱신 시 병렬 다운로드 또는 일괄처리 스크립트를 사용하세요(단, API 호출 제한에 주의).

## 문제 해결
- Parquet가 생성되지 않음
  - `pyarrow` 또는 `fastparquet`가 설치되어 있는지 확인하세요. 권장: `pyarrow`.
  - 로그에 `Parquet 저장 실패` 메시지가 출력되면 해당 예외 내용을 확인하세요.

- 캐시가 갱신되지 않음
  - 스크립트가 다른 캐시 디렉토리를 사용하고 있지 않은지 확인하세요(`Config.FDR_CACHE_DIR`).
  - 권한 문제인지 확인: 캐시 디렉토리에 쓰기 권한이 있는지 확인하세요.
